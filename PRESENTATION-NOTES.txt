ONE HONEST CAVEAT TO SAY OUT LOUD IF ASKED
-----------------------------------------
The repo is design-stage: the algorithm layer, the database schema, and the
security controls are real and runnable; the full Android app UI is still the
Figma prototype, and the Gradle build lands when the app is cut. The checklist
marks each control IMPLEMENTED / SPECIFIED / DESIGN-STAGE so nothing is
overclaimed. The build gate in CI is guarded on ./gradlew for that reason.

HOW THE TWO AGENT SKILLS WERE USED
-----------------------------------
- github.com/cloudflare/security-audit-skill - six-phase adversarial audit
  (reconnaissance, coverage-led hunting, candidate validation, structured
  findings, independent re-verification, reporting). Its pass over this
  repository is docs/SECURITY-AUDIT.md: seven findings, each with an
  action-taken and residual line.
- github.com/OWASP/www-project-agentic-skills-top-10 - the AST10 framework.
  Applied to our own agent tooling in the same document, section 2, because
  the skills that audit the code are themselves agent skills.

Both were also written into the PBL documents themselves:
  IAS Revision 2   -> section 4, "Continuous audit through agent skills"
  ALGOCOM report   -> the section before Task 6, plus a Contents row
